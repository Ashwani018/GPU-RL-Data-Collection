## Comparison of the approaches (N = 262,144 games, K = 1,000 steps)

| Approach | Iterations (K) | Samples (N x K) | Kernel launches | Execution time (ms) | Throughput (samples/s) | Speedup vs CPU | Speedup vs GPU vectorized | Final-state hash |
|---|---|---|---|---|---|---|---|---|
| CPU (1 core) | 1,000 | 262,144,000 | 0 | 1,778,428.639 | 1.474e+05 | 1.0x | 0.0000x | 8380c55af71840f1 |
| GPU vectorized | 1,000 | 262,144,000 | 1,000 | 32.724 | 8.011e+09 | 54,347.1x | 1.0x | 85acfdc0d55a751d |
| GPU fused | 1,000 | 262,144,000 | 1 | 12.364 | 2.120e+10 | 143,842.2x | 2.6x | 85acfdc0d55a751d |

Execution time = time to collect all N x K samples (median over the repetitions, state copy-back to the CPU not included).
Repetitions timed: CPU (1 core) 1, GPU vectorized 10, GPU fused 10 (a single repetition is the one measured time, not a median).
Correctness: GPU vectorized and GPU fused final states bit-identical: YES.
Fusion speedup at the same K (vectorized time / fused time): 2.6x.
The CPU hash can differ from the GPU hash because the CPU and GPU math libraries round sin/cos slightly differently; use scripts/compare.py for the CPU-vs-GPU check.
Fastest approach: GPU fused.
